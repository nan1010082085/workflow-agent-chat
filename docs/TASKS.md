# 落地任务清单

本计划以“给用户完成任务的 Chat”为产品目标。实现顺序必须先收敛用户可理解的对象和交互，再修正状态模型，最后落地界面；不得继续把 Workflow Runtime 的内部概念直接暴露到主工作台。

## 0. 产品基线

| 规则 | 决策 |
|---|---|
| 用户对象 | 用户选择的是“助手”，不是 Workflow；Agent 是后端实现名，普通用户界面不展示 Workflow、Run、HITL、Published 等术语 |
| 会话对象 | 一个会话固定一个助手；会话中不能直接切换助手 |
| 更换助手 | “换一个助手”只创建新会话，原会话保留；已有消息时必须给出新对话提示 |
| 执行对象 | Run/Execution 只用于后端关联、刷新恢复和排障；主界面只展示“处理中 / 需要确认 / 已完成”等用户状态 |
| 处理过程 | 默认展示轻量处理状态；详细处理信息、耗时、日志按需打开，不占据固定右栏 |
| 人工介入 | 审批和补充信息直接出现在聊天流中，移动端也必须可完成 |
| 结果导向 | 结果支持继续追问、复制、下载、重试；失败要说明下一步动作 |

## 1. 迭代顺序

| ID | 类型 | 优先级 | 任务 | 完成标准 |

| P-01 | 产品 | P0 | 冻结用户对象和术语 | UI 文案统一使用“助手 / 对话 / 处理状态 / 需要确认 / 处理信息”；Workflow、Run、Execution、HITL 不出现在普通用户主路径 |

## 推荐执行顺序

1. 先完成 `P-01`-`P-05`，同步更新 PRD、领域契约和 UIUX。
2. 再完成 `B-01`-`B-07`，先保证“一个会话固定一个助手”和状态闭环正确。
3. 完成 `F-01`-`F-07`，把聊天主路径从“运行控制台”改成“任务对话”。
4. 完成 `F-08`-`F-10` 与 `D-01`-`D-04`，验证助手发现、结果、等待和错误状态。
5. 最后完成 `O-01`-`O-04`；SSE、文件和自动路由不前置到 MVP。

## MVP 完成定义

- 用户打开后能选择一个助手并直接开始一段对话。
- 一个会话始终只服务一个助手；换助手不会污染原会话上下文。
- 处理中只显示对用户有帮助的状态；详细处理信息按需查看。
- 需要确认的任务可以直接在聊天流完成，桌面和移动端一致可用。
- 成功、失败、取消、刷新恢复、Runtime 不可用和重复提交都有明确行为。
- 普通助手和需确认助手各通过自动化测试与 UI/UX 验收。
